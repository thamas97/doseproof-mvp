# Contribution workflow

1. Read your real DPM task and contract v0.1. Confirm inputs before moving Backlog to Ready.
2. Pull main and create a short branch such as DPM-123-baseline-model using the actual assigned key.
3. Keep to your owned modules. Contracts, integration interfaces and shared configuration require agreement by all affected members.
4. Use ChatGPT to clarify, Codex to implement/test, Claude in the browser to challenge selected changes, and the named human reviewer to accept.
5. Open a small pull request with the real issue key in branch, commit and title. Include actual checks, evidence references and remaining defects.
6. Do not let two tools edit one working directory concurrently. Do not commit credentials, databases, node_modules or generated capture files.
7. Merge only after another member review; this is a team rule even if the hosting plan cannot enforce it. Do not self-approve.
8. Done requires observable acceptance, saved evidence and human reviewer confirmation. A scaffold, AI response or passing contract-format check is not runtime acceptance.
